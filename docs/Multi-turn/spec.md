# MewCode 第一阶段纯对话 Spec

## 背景

MewCode 是一个命令行 AI 助手，目标形态类似 Claude Code。本阶段只建立最小可用的交互式对话能力：用户在终端启动程序后进入对话界面，输入问题，程序调用大模型 API，并将模型回复以流式方式打印到终端。

当前阶段不实现代码编辑、文件操作、工具调用或自动执行任务能力。重点是把终端交互、LLM Provider 抽象、配置驱动切换后端、SSE 流式响应和多轮上下文记忆打牢。

## 目标

- 用户可以在终端中启动 MewCode 并进入交互式对话界面。
- 用户输入消息后，MewCode 调用配置指定的大模型后端。
- 模型回复必须以流式方式显示在终端中，而不是等待完整结果返回后一次性输出。
- 当前运行会话内支持多轮对话，模型可以基于之前的对话内容继续回答。
- OpenAI 与 Anthropic Claude 两类 API 后端可通过 YAML 配置切换。
- Provider 层具备统一抽象，后续可以较低成本接入新的 LLM 后端。

## 功能需求

- F1: 启动程序后进入终端交互式对话界面，用户可以连续输入消息。
- F2: 用户输入普通文本后，程序将其作为用户消息发送给当前配置的 LLM 后端。
- F3: 模型回复通过 SSE 流式读取，并在终端中随着增量内容到达逐步打印。
- F4: 程序在当前进程内保存多轮对话历史，并在后续请求中携带历史消息。
- F5: 程序支持 OpenAI 协议后端，至少能发送聊天请求并解析流式文本增量。
- F6: 程序支持 Anthropic Claude 协议后端，至少能发送 Messages 请求并解析流式文本增量。
- F7: 程序支持 Claude extended thinking 的配置开关和预算参数，并在启用时向 Anthropic 请求中传递相应配置。
- F8: 程序通过 YAML 配置文件读取 LLM 供应商信息，核心字段包括 `protocol`、`model`、`base_url`、`api_key`。
- F9: 程序根据 `protocol` 字段选择对应 Provider；未知协议必须给出清晰错误。
- F10: 用户可以退出对话，并可以在当前运行中清空对话历史。
- F11: 当配置文件不存在或必填字段缺失时，程序给出可操作的错误提示，而不是静默失败。

## 非功能需求

- N1: 流式输出必须基于 SSE 增量处理，避免把完整响应读完后再统一打印。
- N2: Provider 抽象不得泄漏具体供应商的请求细节给终端交互层。
- N3: API Key 不应硬编码在源码中，也不应要求重新编译才能切换。
- N4: 配置格式应便于本地开发和后续扩展，新增可选字段不能破坏四个核心字段。
- N5: 终端输出应清晰、稳定，错误提示应能指导用户下一步操作。
- N6: 本阶段实现应保持边界收敛，避免提前引入 agent 工具系统、文件系统权限模型或代码编辑流程。

## 不做的事

- 不做 tool use。
- 不读写用户项目文件。
- 不执行 shell 命令。
- 不做代码编辑、diff、patch 或自动提交。
- 不做长期记忆或跨进程会话持久化。
- 不做复杂 TUI 布局、侧边栏、历史浏览器或多标签界面。
- 不实现非 OpenAI / Anthropic 的第三方协议适配，除非它们兼容已支持协议。

## 验收标准

- AC1: 在终端启动 MewCode 后，用户能看到交互式输入提示并输入消息。
- AC2: 使用有效 OpenAI 配置时，输入一条消息后能看到模型回复逐步打印到终端。
- AC3: 使用有效 Anthropic 配置时，输入一条消息后能看到模型回复逐步打印到终端。
- AC4: 连续两轮对话中，第二轮问题能引用第一轮内容并得到上下文相关回答。
- AC5: 修改 YAML 中的 `protocol`、`model`、`base_url`、`api_key` 后，无需改代码即可切换后端或模型。
- AC6: 启用 Claude extended thinking 配置时，Anthropic 请求包含 thinking 相关参数。
- AC7: 配置文件缺失时，程序打印如何指定或创建配置文件的提示。
- AC8: 配置必填字段缺失时，程序明确指出缺失字段。
- AC9: 用户输入退出命令后，程序正常结束。
- AC10: 用户输入清空命令后，当前会话历史被清空，后续对话不再携带清空前的消息。
- AC11: 代码结构中存在统一 Provider 抽象，终端交互逻辑不直接依赖 OpenAI 或 Anthropic 的具体请求格式。
